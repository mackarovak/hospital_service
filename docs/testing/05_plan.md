# План тестирования

## 1. Общие сведения

Проект: MedCat.
Объект: веб-приложение электронной медкарты.
Версия стенда: локальный Docker Compose от 25.11.2026.
Цель: подтвердить работоспособность критичных сценариев пациента и врача, выявить дефекты авторизации, валидации, API и UI.

## 2. Область тестирования

Включены: регистрация, login/logout, роли, профиль, медкарта, запись на приём, расписание врача, triage, REST API, база данных, Docker Compose, UI, smoke/load-тесты.

Не включены: клиническая достоверность медицинских решений, реальные интеграции с МИС, сертификация медицинского ПО, production-нагрузка.

## 3. Типы проверок

- unit-тестирование;
- интеграционное тестирование;
- API-тестирование;
- UI/E2E-тестирование;
- исследовательское тестирование;
- security smoke-тесты;
- responsive UI-тесты;
- smoke/load/stress-тесты k6;
- регрессионное тестирование исправлений.

## 4. Методы тестирования

- эквивалентное разбиение;
- граничные значения;
- таблицы решений;
- проверки по таблицам состояний;
- pairwise-комбинации роли и endpoint;
- exploratory testing;
- сценарное тестирование;
- error guessing;
- повторный прогон после исправлений.

## 5. Приоритеты

P0: безопасность и аутентификация, роли, медкарта, бронирование.
P1: профиль, triage, расписание, запись и отмена.
P2: пагинация, поиск, печать, UX.
P3: косметика и редкие сочетания viewport.

## 6. Среда

- macOS;
- Docker Compose;
- PostgreSQL 16;
- Python 3.12/Django 6.1.3;
- React/TypeScript/Vite;
- Chromium для ручного desktop/mobile-прогона;
- pytest и pytest-django;
- Vitest;
- k6.

Адреса: `http://localhost`, `http://localhost:8000/api/v1`, `http://localhost:3000`.

Демо-пользователи:

- patient1/password — пациент;
- doctor1/password — врач.

## 7. Критерии входа

- Docker Compose поднят;
- backend health-check доступен;
- frontend доступен;
- база создана и seed выполнен;
- тестовые инструменты установлены;
- тестовые данные восстановлены.

## 8. Критерии выхода

- все P0 тесты выполнены;
- результаты backend и frontend наборов известны;
- Critical и High дефекты описаны;
- k6 smoke выполнен, пороги и отклонения зафиксированы;
- ручной UI-прогон выполнен по checklist;
- результаты зафиксированы в отчёте;
- баги имеют воспроизведение и статус.

## 9. Дефекты и приостановка

Тестирование приостанавливается при недоступности backend/frontend, неработающей PostgreSQL, ошибке контейнера или невозможности восстановить seed-контекст.

## 10. Роли

- Тест-лид/инженер: планирование, ручные проверки, документация;
- Автор автоматизации: pytest, Vitest, k6;
- Разработчик: исправление дефектов и повторная проверка;
- Защита проекта: демонстрация методов и результатов.
