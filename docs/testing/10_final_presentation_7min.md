# Презентация MedCat — итоговый проект

Время: 7 минут.

## Слайд 1. Титульный — 20 сек

MedCat — тестирование веб-приложения электронной медкарты.
Показать: предмет тестирования, роли, Docker-среду.

## Слайд 2. Объект и подходы — 55 сек

Приложение кросс-платформенное по способу использования в браузере:

- React/TypeScript frontend;
- Django REST Framework backend;
- PostgreSQL;
- Docker Compose;
- роли Пациент и Врач;
- desktop Chromium и ручной responsive-сценарий.

Подходы: API-first для критичных данных, UI-тесты для сценариев пользователя, k6 для нагрузки.

## Слайд 3. Исследовательское тестирование — 55 сек

Показать три первых дефекта:

- пробелы в обязательном ФИО сохраняются;
- врач может создать пересекающиеся окна приёма;
- пациент может забронировать прошедший слот через API.

Подтвердить позитивные сценарии: 401, 403, health и triage.

## Слайд 4. Видовое покрытие — 55 сек

Проведено и запланировано:

- unit: модели, triage, React-компоненты;
- integration: auth, seed, Django ORM;
- API: роли, медкарта, профиль, слоты;
- UI: login и компоненты;
- exploratory: некорректный ввод;
- load: k6 smoke;
- regression и security smoke;
- responsive — вручную перед защитой.

## Слайд 5. Методы и тест-кейсы — 55 сек

Использованы:

- эквивалентное разбиение;
- граничные значения;
- таблица решений;
- state transition;
- pairwise-роли и endpoints;
- error guessing.

Показать TC-001 вход пациента, TC-003 запрет роли, TC-007 бронирование прошедшего слота, TC-010 слоты.

## Слайд 6. Риски и автоматизация — 55 сек

Основные риски: чужая медкарта, пересекающиеся слоты, бронирование прошедшего slot, неверный triage, JWT и перегрузка.

Автоматизация:

- pytest: backend/API/модели;
- Vitest: React-компоненты и login UI;
- k6: HTTP-load;
- Docker: воспроизводимый запуск.

Причина выбора: критичные роли и данные лучше проверять быстро на API, UI-компоненты — локальными unit-тестами, нагрузка — k6.

Показать код login-теста или pytest-кейса и команду `make test`.
