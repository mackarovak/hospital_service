# Программа и методика испытаний

## ПМИ-01. Назначение

Программа определяет порядок проверки MedCat в локальном Docker-окружении.

## ПМИ-02. Испытательные уровни

### 1. Модульное тестирование

Цель: проверить отдельные классы, функции и React-компоненты.
Инструменты: pytest, Vitest.
Проверки: hash/verify пароля, JWT, triage, уникальность моделей, компоненты frontend.
Команды:

```bash
make test-backend
make test-frontend
```

### 2. Интеграционное тестирование

Цель: проверить Django ORM, seed и взаимодействие auth-сервисов.
Команда:

```bash
docker compose exec backend python -m pytest -v -m integration
```

### 3. API-тестирование

Цель: проверить HTTP-контракты и разграничение ролей.
Команда:

```bash
docker compose exec backend python -m pytest -v -m api
```

Критерии: 2xx на валидный запрос, 400 для некорректных данных, 401 без auth или неверных credentials, 403 при неверной роли, 409 при занятом resource.

### 4. UI-тестирование

Цель: проверить сценарии React-интерфейса и адаптивность.
Инструменты: Vitest для компонентных/UI-тестов, ручной Chromium-прогон для визуальной проверки.
Команды:

```bash
make test-frontend
```

Основные сценарии:

- доступность `/login`;
- вход пациента;
- вход врача;
- неверный пароль;
- переход в нужный dashboard;
- сохранение токена и роли;
- desktop и mobile viewport.

Playwright исключён из финальной автоматизации из-за тяжёлой загрузки и несовместимости image/pin в стенде.

### 5. Нагрузочное тестирование

Цель: проверить доступность и задержки под нагрузкой.
Инструмент: k6.
Команда:

```bash
make test-load
```

Используемые сценарии: smoke, read, workflow, stress.

## ПМИ-03. Исследовательские методы

В исследовательском прогоне проверяются комбинации неожиданного ввода: пробелы, HTML-теги, SQL-подобные строки, длинный текст, future/past-датa, неподдерживаемые enum-значения.

## ПМИ-04. Техника оценки результата

Результат Passed: фактический соответствует ожидаемому.
Failed: существует расхождение с требованиями.
Blocked: среда или зависимость не позволяют выполнить проверку.
Skipped: проверка не входит в текущий набор или не разрешена стендом.

## ПМИ-05. Уровни дефекта

- Critical: кража чужих данных, обход роли, потеря медкарты;
- High: серверная ошибка 500, невозможность критической операции;
- Medium: некорректная валидация или UX;
- Low: текстовая, косметическая или редкая проблема.

## ПМИ-06. Последовательность выполнения

1. Запуск среды и seed.
2. Backend pytest.
3. Frontend Vitest.
4. k6 smoke/load.
5. Исследовательская проверка UI/API.
6. Регистрация дефектов.
7. Исправление разработчиком.
8. Ретест и regression run.
9. Формирование отчёта.

## ПМИ-07. Единая команда

```bash
make test
```

Команда выполняет backend pytest, frontend unit/UI и k6 smoke из корня проекта.
