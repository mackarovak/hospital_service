# План презентации итогового проекта

Рекомендуемая длительность: 10–15 минут.

## Слайд 1. Титульный

- MedCat — тестирование веб-приложения;
- тема итогового проекта;
- автор и группа.

## Слайд 2. Предмет тестирования

- приложение и архитектура;
- роли patient/doctor;
- frontend/backend/PostgreSQL/Docker;
- границы тестирования.

## Слайд 3. Исследовательское тестирование

- проведённый exploratory-прогон;
- HTTP-проверки;
- первые найденные дефекты;
- screenshots или терминальный прогон.

## Слайд 4. Виды тестирования

- unit/integration/API/UI;
- security;
- performance/load;
- responsive/UX;
- regression.

## Слайд 5. Методы тестирования

- граничные значения;
- эквивалентные классы;
- таблицы решений;
- state transition;
- exploratory testing;
- error guessing.

## Слайд 6. Функциональность и тест-кейсы

- авторизация;
- роли;
- профиль;
- медкарта;
- запись;
- triage;
- расписание;
- примеры TC-001…TC-011.

## Слайд 7. Риски

- доступ к чужой медкарте;
- двойное бронирование;
- некорректная валидация;
- 500 error;
- загрузка под нагрузкой;
- ошибки окружений.

## Слайд 8. Автоматизация

Пояснить причину выбора:

- pytest: backend/API и модели;
- Vitest: быстрые React unit/UI-тесты;
- k6: HTTP-нагрузка;
- Docker: воспроизводимый запуск.

Показать `make test` и отдельные команды.

## Слайд 9. Найденные дефекты

Для каждого: ID, severity, шаги, фактический/ожидаемый результат и скриншот.

## Слайд 10. Результаты прогона

- backend 46/46;
- frontend 4/4;
- k6 915 итераций, p95 222.62 ms;
- найдено 3 дефекта и одно k6 наблюдение.

## Слайд 11. Скринкаст и защита UX

Короткое видео 2–5 минут:

- вход;
- роль;
- профиль;
- запись;
- запуск тестов;
- демонстрация дефекта.

## Слайд 12. Выводы

- что работает;
- что требует исправления;
- какие риски закрыты;
- дальнейшие шаги;
- качественная оценка подготовки приложения.
