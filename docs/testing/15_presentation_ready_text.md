## Слайд 4 — Исследовательское тестирование

В результате исследовательского тестирования обнаружены три дефекта:

1. Пробелы принимаются вместо обязательного ФИО.
2. Врач может создать пересекающиеся окна приёма.
3. Пациент может забронировать прошедший slot через API.

Корректно работают:

- неправильный пароль — HTTP 401;
- неизвестный пользователь — HTTP 401;
- пациент не открывает врачебные endpoints — HTTP 403;
- врач не открывает patient endpoints — HTTP 403.

## Слайд 12 — BUG-001

**Пробелы сохраняются вместо обязательного ФИО**

Фактический результат:

- PATCH-запрос со строками из пробелов получил HTTP 200;
- пробельные значения сохранены в профиле.

Ожидаемый результат:

- HTTP 400;
- пробельные данные не сохраняются.

Серьёзность: Medium.  
Приоритет: Medium.

---

## Слайд 13 — BUG-002

**Пересекающиеся окна приёма**

Шаги:

1. Создать слот 10:00–11:00.
2. Создать слот 10:30–11:30.

Фактический результат:

- оба запроса получили HTTP 201;
- слоты пересекаются.

Ожидаемый результат:

- второй слот отклоняется HTTP 400 или HTTP 409.

Серьёзность: Medium.  
Приоритет: High.

---

## Слайд 14 — BUG-003

**Можно забронировать прошедший slot**

Шаги:

- выполнить POST `/api/v1/patient/slots/{slot_id}/book` для прошедшего slot.

Фактический результат:

- получен HTTP 200;
- прошедший slot привязан к пациенту.

Ожидаемый результат:

- HTTP 400 или HTTP 409;
- slot остаётся свободным.

Серьёзность: High.  
Приоритет: High.
