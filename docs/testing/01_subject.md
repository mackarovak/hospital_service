# Шаг 1. Предмет тестирования

## Выбранное приложение

MedCat — кросс-платформенное веб-приложение электронной медицинской карты.

Приложение состоит из:

- React + TypeScript frontend;
- Django REST Framework backend;
- PostgreSQL базы данных;
- Docker Compose для локального запуска;
- k6 нагрузочных тестов;
- Grafana/Loki/Prometheus наблюдаемости;
- Kubernetes-манифестов для stage-среды.

## Тип приложения

Веб-приложение с адаптивным интерфейсом для браузера. Тестирование будет выполняться преимущественно в Chromium, поскольку это наиболее распространённый браузерный сценарий для пользовательской защиты и автоматизации.

Дополнительно рассматриваются:

- Desktop-browser сценарии с шириной обычного экрана;
- responsive UI в мобильном viewport;
- API-клиентское тестирование;
- нагрузочное тестирование HTTP-интерфейсов;
- инфраструктурные и deployment-проверки.

## Основные роли

- Пациент;
- Врач;
- Неавторизованный пользователь.

## Основные сценарии

1. Регистрация и вход.
2. Просмотр и изменение профиля пациента.
3. Просмотр собственной медицинской карты.
4. Подбор специальности врача по симптомам.
5. Просмотр врачей и запись на свободный слот.
6. Просмотр и отмена приёмов пациента.
7. Просмотр пациентов врача.
8. Просмотр медкарты и создание/изменение записей врача.
9. Управление рабочими окнами приёма врача.
10. Проверка разграничения прав доступа.

## Включено в тестирование

- Функциональность пользовательского интерфейса;
- REST API;
- авторизация и роли;
- целостность данных;
- валидация полей;
- браузерные сценарии;
- UI на разных размерах экрана;
- ошибки и некорректные данные;
- smoke и нагрузочные сценарии;
- база данных и health-check.

## Исключено из тестирования

- Реальные медицинские клинические решения;
- сертификация медицинского ПО;
- внешние платёжные системы;
- интеграции с ЕМИАС/МИС, отсутствующие в приложении;
- физическая совместимость с реальным оборудованием;
- нагрузка на production-кластер, если она не одобрена владельцем стенда.

## Окружения

- Local: Docker Compose;
- API: `http://localhost:8000/api/v1`;
- UI: `http://localhost`;
- Grafana: `http://localhost:3000`;
- Kubernetes/stage: указывается в отчёте отдельно после получения стенда.

## Артефакты шага

- Описание предмета тестирования;
- границы тестирования;
- роли пользователей;
- основные пользовательские сценарии;
- состав тестовой среды.
