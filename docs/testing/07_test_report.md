## 4. Исследовательские дефекты

Подтверждены корректно:

- неправильный пароль — HTTP 401;
- неизвестный логин — HTTP 401;
- пациент не открывает doctor endpoint — HTTP 403;
- врач не открывает patient endpoint — HTTP 403;
- пустой triage — HTTP 400;
- прошлое время слота — HTTP 400;
- reversed interval слота — HTTP 400;
- имя длиной 101 символ — HTTP 400;
- телефон длиной 31 символ — HTTP 400;
- future date — HTTP 400;
- invalid date — HTTP 400.

Выявлены дефекты:

- DEF-001: пробелы в обязательных полях;
- DEF-002: пересекающиеся окна приёма;
- DEF-003: бронирование прошедшего слота через API.

## 7. Риски и ограничения

- локальная среда не подтверждает Safari и production-мобильные браузеры;
- production-нагрузка не проводилась;
- triage является rule-based, не клиническим решением;
- единичные k6 failed-check требуют повторного smoke-прогона;
- UI-ретест нужен после исправления DEF-001–DEF-003.

## 8. Вывод

Backend и frontend наборы прошли полностью. k6 thresholdы прошли при p95 222.62 ms и fail rate 0.10%. Основные сценарии авторизации и разграничения ролей подтверждены. Для закрытия проекта требуется исправить три дефекта валидации и повторить smoke-прогон для единичных failed-check.

## 9. Решение

Релиз условно готов к дальнейшему тестовому циклу. Критически не закрыты тестовые дефекты профиля. Финальная регрессия должна включать повторный backend pytest, frontend Vitest и k6 smoke.
